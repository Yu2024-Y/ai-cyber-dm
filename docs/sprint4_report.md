## 三、关键改进（对比 Sprint 3）
- **多人能力**：战役独立存档、角色唯一占用、消息增量同步 + nonce 去重（多标签/多设备同局）
- **结算协议（grounding）**：成败由外部骰子工具真随机结算并落库，再回灌上下文；模型只能按真实结果续写，从机制上抑制幻觉
- **检定门控**：高风险行动提示难度并等待掷骰，掷完自动结算；日常乱掷轻处理
- **DM 质量**：主持人操作框架 + 每轮状态栏 + 长局摘要折叠 + 关键信息高亮
- **结局机制**：一局默认 10 幕，达上限自动终章；支持手动结束生成结局
- **稳健性**：输入防护（注入拦截）、场景图本地缓存（避免链接过期）、模型异常本地兜底

## 四、质量与验证
- 全量 `pytest`（单元 + API 集成，含边界用例）与 `ruff` 通过
- CI 双流水线：`测试与代码质量`、`镜像构建与推送`（GHCR）；每个 PR 合并前均需 CI 绿 + 队友 approve
- 浏览器端到端：大厅 → 选角 → 多标签同局 → 对话 / 掷骰自动结算 / 场景卡 / 剧情树 / 语音 / 终章结局
- Docker：`docker compose up -d --build` 一键起服，`/health` 探活通过

## 五、复盘
- **教训**：早期改动集中在 `routes.py`、`static/*` 等共享文件，故采用"单文件集中提交 + 依赖顺序分批判"策略（数据层 → 引擎 → worker → 路由 → 前端），并在合并前做**本地预演（main + 全部批次覆盖 → 跑测试）**验证等价性，避免大规模冲突
- **协作**：批次 PR 分别由 A/B/C 提交、交叉审核合并；看板按 Backlog → Todo → In Progress → In Review → Done 流转
- **遗留/边界**：目标驱动结局、输出后验校验、RAG 检索、并发压测均未实现，作为后续方向
