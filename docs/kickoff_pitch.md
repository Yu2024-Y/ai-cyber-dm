# Kick-off 选题 Pitch（5 分钟宣讲提纲）

课程：工程实践（基于敏捷方法的 AI 原生应用开发实践）
日期：2026-08-29（Day 2 下午）｜ 时长：5 分钟

## 一句话定位

用大模型当主持人的无限跑团引擎：玩家负责编故事，AI 负责当裁判、演 NPC、出场景图、念台词。

## 1. 痛点与创意

- 传统跑团/剧本杀最大的门槛是缺一个靠谱的 DM：要编剧情、记规则、演 NPC、做判定，门槛高
- 方案：用 DeepSeek-V4-Flash 扮演 DM，玩家自由输入任意指令，AI 实时主持、判定、推进剧情
- 剧情配合场景图渲染和 AI 语音播报，增强沉浸感，剧情永不重复

## 2. 核心功能演示要点

| 能力 | 演示表现 |
|------|---------|
| 自由指令主持 | 玩家输入"我想撬开那扇门"，AI 即时回应剧情 |
| 骰子检定 | 输入"检定力量"，系统掷 d20 + 判定成功/失败，剧情随结果分支 |
| 场景/角色卡 | 触发剧情时异步生成场景卡、NPC 画像 |
| 语音播报 | 关键剧情用 edge-tts 中文配音播报 |

## 3. 技术难点与解法

1. 多轮上下文记忆：滑动窗口 + 摘要压缩，历史不丢、上下文不爆
2. 结构化数值检定：Pydantic v2 强校验，LLM 输出骰子结果自动解析，杜绝乱判
3. SSE 流式 + 生图异步：文本 SSE 流式即时输出；生图走后端队列（限流 2 次/分），完成后 SSE 推送，玩家无等待感知

## 4. 架构与技术栈

- 分层架构：前端（原生 Web）→ API 层 → 服务层（DM引擎/骰子检定/生图队列/TTS）→ 领域层（Pydantic 契约 + 状态机）
- 外部依赖：SiliconFlow（DeepSeek-V4-Flash + Qwen-Image）+ edge-tts + SQLite
- 技术栈：FastAPI + SQLite + 原生 JS，全 Python，团队上手快
- 质量防线：Tenacity 重试、API 限流、Prompt 注入防护、mock 降级

## 5. 创新点

- 自由输入：玩家想做什么就做什么，AI 实时判定，非固定选项
- 无限剧情：剧情永不重复，天然可复玩
- 多模态输出：文本 + 图像 + 语音三通道
- 工程化：完整 BDD/TDD、CI/CD、Docker、结构化文档

## 6. 团队分工与节奏

| 角色 | 职责 |
|------|------|
| A | 架构、文档、LLM 接入 |
| B | 后端骨架、数据层、测试 |
| C | 生图 / TTS 接入、CI、前端 |

10 天 4 Sprint：骨架(1) → MVP 核心(2) → 体验与防御(3) → CI/CD 与答辩(4)
